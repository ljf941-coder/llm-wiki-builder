# llm-wiki-builder

一个用于构建和改造个人 LLM Wiki 的 Agent Skill。它指导 AI 根据个人生活、学习和工作场景，建立可追溯、可迁移、适合多个 AI 工具协作维护的知识库。

该技能适合需要长期积累和复用个人知识、项目经验与决策的人；它不用于初始化普通软件项目文档。

## 能做什么

- **梳理现状与目标**：检查现有入口、目录、来源、规则和自动化，保留已有数据与工具适配。
- **设计知识结构和权限**：区分原始材料、候选内容、正式知识、用户原话和处理状态，明确修改、冲突及授权规则。
- **整理来源与项目经验**：根据用户选择设计采集、版本识别、去重、提炼和归档流程；项目资料先参考项目入口及知识地图。脱敏快照只用于来源追溯，正式知识需另行筛选可复用事实、结果、决策、问题解决过程与经验。
- **会话标题**：依据会话内容生成中文主标题，保留来源标识，并在生成前后进行局部脱敏；标题命中疑似凭据时脱敏或重新概括，不阻断整个来源。
- **职业导航**：按公司、项目和时间节点组织职业记录；区分公司与项目参与区间和项目里程碑，保留来源及待确认的简历候选。
- **保留来源与不确定性**：区分用户明确表达、来源事实、助手历史报告、AI 推断和待确认事项，记录来源、处理状态及覆盖不足的范围。状态区分「已采集」「待整理」「部分提炼」「已整理」，导入或少量摘要不等于整场已整理。
- **跨系统与迁移**：识别运行平台并分别验证采集和调度，使用库内相对链接与可配置来源映射，标明缺失或未验证的依赖。
- **支持安全与迁移**：对疑似密钥、令牌、数据库账号密码和带凭据连接串做本地局部脱敏后继续处理，保留其余有用内容与普通无害 URL；原值不得进入标题、文件名、索引、状态、日志或错误输出。不可信来源标识以不可逆稳定摘要写入索引、文件名和快照头，避免简单脱敏造成碰撞。经授权可对既往因凭据被整条阻断的来源重新脱敏并写入新版本，不覆盖只读旧快照。
- **协作与自检**：共享知识库规则和脱敏契约，各工具独立维护会话发现、导出和整理链路；按工具使用经授权的自检会话检查规则。

本仓库提供的是指导 Agent 工作的 `SKILL.md`，外加一份标准库参考实现，用于演示脱敏契约和只读快照版本管理。它不是现成的知识库应用、完整采集器或自动调度服务，也不表示目标知识库里的各适配器已经迁移到本契约。具体采集、接入、调度、审核和备份需要结合环境与授权另行配置和验证。

## 安装

将仓库克隆到支持 Agent Skills 的工具所使用的技能目录，目录名保持为 `llm-wiki-builder`。例如，安装为当前用户的 Codex 技能：

```bash
git clone https://github.com/ljf941-coder/llm-wiki-builder.git ~/.codex/skills/llm-wiki-builder
```

Windows PowerShell：

```powershell
git clone https://github.com/ljf941-coder/llm-wiki-builder.git "$env:USERPROFILE\.codex\skills\llm-wiki-builder"
```

其他工具的技能目录和加载方式可能不同，请参照对应工具的文档。也可下载本仓库，将包含 `SKILL.md` 的文件夹复制到该工具支持的技能目录；安装后按工具要求重新加载技能或重启会话。

## 使用

在支持技能的 AI 助手中，以自己的目标描述任务，例如：

> 使用 llm-wiki-builder 帮我从零设计个人知识库，整理工作、学习和生活资料。先检查我的需求，再给出可实施的结构。

也可以改造现有知识库：

> 使用 llm-wiki-builder 检查当前知识库的入口、来源和整理流程，保留已有内容，补充可追溯和自检机制。

说明现有目录、可访问的来源、希望采集的范围，以及是否允许 AI 直接归档。涉及用户原话、敏感资料或已有文件的修改时，遵循知识库现有规则和用户授权。

## 工作流程

1. 了解目标、使用场景和既有知识库。
2. 设计共享入口、区域规则、来源与状态管理。
3. 按实际需要实施采集、整理、关联、检索和备份；快照落盘和发送模型前先做局部脱敏，归档前再检查。
4. 检查链接、来源、重复运行、失败处理和不确定事项。
5. 汇报实际完成的工作、验证结果和仍需配置的部分。

规则变更后，使用当前工具经授权的专属自检会话检查正向和负向检索。未验证自动创建和投递能力时，由用户手动创建并指定；无法发送时报告缺口。已有会话带有历史上下文，不能当作全新会话的冷启动测试。

## 参考实现与测试

仓库内 `scripts/sensitive_guard.py` 和 `scripts/snapshot_store.py` 是面向共享脱敏契约的最小参考实现，仅依赖 Python 3.9+ 标准库。在仓库根目录运行：

```bash
python3 -m unittest discover -s tests -v
```

Windows：

```powershell
python -m unittest discover -s tests -v
```

测试只用明显虚构的凭据样本，覆盖局部替换并保留上下文、多行私钥（含传统头、CRLF 与 PGP）整块清除、带凭据 URL（含空用户名连接串）脱敏、普通 URL 保留、重复脱敏幂等、脱敏后复检、重复导入去重、源标识哈希防碰撞与新版本，以及旧快照不被覆盖；并对落盘目录做全树扫描，确认虚构原值不出现在文件名、快照或状态中。测试失败信息不会回显凭据原值。这些测试只验证参考实现，不连接真实会话、模型或数据库，也不宣称调度或目标库适配器已完成迁移。

## 边界

工具能访问哪些会话、文件和外部来源，取决于实际连接与权限；安装技能本身不会自动接通来源或开启后台任务。对来源不足的内容应标为待确认。敏感信息检测存在盲区，不能保证覆盖所有形式，也不能宣称零遗漏。权限拒绝仍须遵守，不得借其他工具或链路绕过。
